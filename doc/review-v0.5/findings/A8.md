## VERDICT (short form)

"Announcing costs nothing" is **FALSE as stated, but only narrowly**. husk v0.5's
attribution — the `husk:` prefix plus the submit-path `sbatch failed: sbatch: error:`
wrapper — is a **reliable, byte-stable, free instrument** (it meets the brief's three
"instrument" properties) that does two things enumeration alone does not do *mechanically*:
  (1) it classifies **husk-policy-refusal vs cluster-refusal** with a grep, not an inference;
  (2) it lets an agent **read husk's gate-state for a chosen sbatch option WITHOUT running
      the job**, by pairing the option with a guaranteed cluster-side reject.
That is a genuine **capability**, demonstrated below (inputs A/B and C/D).

BUT the capability **delta over husk's own verbosity is small**, and this is the honest core
of the result: husk already discloses the whole boundary *in prose* (every refusal names the
gated option and why; the query refusal enumerates the entire allowlist). The prefix therefore
upgrades a *fallible content-inference* ("does this read like husk's voice or SLURM's?") into a
*mechanical, perfectly-reliable classifier* — it does not hand over a map the agent could not
otherwise read. And removing the attribution would **degrade legitimate compliance** (the honest
agent needs to know who refused it — exactly what husk's own die() docstring argues), so it is a
**trade-off, not a free fix**. Net: mostly convenience, with one narrow demonstrated capability
(non-executing gate-probing). The teaching-errors design largely survives; the slogan does not.

Timing is a **null** oracle. The masked-file "shape" banner is **convenience** (masks self-advertise
as char devices) with one caveat (the ENOENT-reconstructed-home case). "No network is policy not
transient" is **convenience** (redirects effort, opens nothing).

## METHOD

In-cage, Bash only. Exercised the error/refusal paths of the husk SLURM broker (sbatch + the
read-only query stub) and the filesystem/network layers, and compared messages, exit codes,
timing, and byte-stability across inputs chosen to differ in exactly one piece of trusted state.
All sbatch probes were guarded (`--nodes=1000000`, impossible `--time`, or a bogus `--constraint`)
so nothing could queue/run, except ONE sanctioned minimal job (1 node, 20s, /bin/true) to capture
the success-note path; that job (5010169) was cancelled and its artifacts removed.

## THE DEMONSTRATED ORACLE (this is the finding the brief asks to be *shown*)

### Submit path — "husk policed it" vs "husk forwarded it, the cluster refused"
Two inputs identical except for one option; guarded so NEITHER runs a job:

  A  sbatch --partition=short --time=00:01:00 --nodes=1000000  <script>
     -> husk: husk brokers single-node jobs only, but this asks for --nodes=1000000. ...
        [NO "sbatch failed:" -> husk POLICY owns the refusal]

  B  sbatch --partition=short --time=00:01:00 --constraint=husk_bogus_feat_zzz  <script>
     -> husk: sbatch failed: sbatch: error: Batch job submission failed: Invalid feature specification
        [the "sbatch failed: sbatch: error:" wrapper -> husk FORWARDED it; the CLUSTER refused]

Trusted state distinguished: **which layer owns the refusal** — i.e. whether a given sbatch
option is inside husk's policy gate or passed through to the real scheduler. Byte-identical on
retry (verified 3x). Free (no job runs). Reliable (mechanical marker). => an instrument.

### Query path — "husk refused the flag" vs "the cluster answered/errored"
  C  squeue --this-is-not-a-real-flag
     -> husk: husk does not forward "--this-is-not-a-real-flag" to squeue. ... For squeue husk
        accepts: --account --all --array --clusters --format --jobs --json --long --me --name
        --nodelist --noheader --partition --qos --sort --states --steps --user --yaml. ...
        [`husk:` prefix -> husk gate]

  D  squeue --jobs=999999999
     -> slurm_load_jobs error: Invalid job id specified
        [NO `husk:` prefix, raw SLURM text -> the command was forwarded; the cluster answered]

Trusted state distinguished: husk-refused vs cluster-reached, on the read-only query path.

### Why this rises toward CAPABILITY, not just convenience
Pairing a *target* option with a guaranteed cluster-side reject (as in B) lets an attacker ask
"does husk gate option X?" and read the answer from the presence/absence of the `sbatch failed:`
wrapper **without ever executing a job**. That is a non-destructive gate-probe of husk's option
registry — a measurement, not a guess.

### Why the delta is nonetheless BOUNDED (the honest counterweight)
- The message CONTENT already identifies the layer even with the prefix stripped: husk speaks in
  full sentences about itself ("husk submits...", "husk does not forward...", "husk confines...");
  SLURM is terse and SLURM-shaped ("slurm_load_jobs error:", "Batch job submission failed:"). The
  prefix converts a *fallible* content-inference into a *mechanical* one; it does not create a
  distinction that was absent.
- The boundary is disclosed WHOLESALE regardless of the prefix: the query refusal (C) lists the
  entire 19-option allowlist; each submit refusal names the exact option it gates and the reason.
  So no binary-search is needed — the map is handed over in prose. The discriminator's unique
  contribution (reading gate-state without running the job) is real but narrow.

## PER-CANDIDATE ANALYSIS

### ★1 Attribution as a one-bit channel  => INSTRUMENT, bounded capability (see "DEMONSTRATED
ORACLE" above). Strongest candidate, and it does NOT come back fully null: the prefix + the
`sbatch failed:` wrapper form a mechanical, byte-stable, free classifier of husk-vs-cluster
refusal, and enable non-executing gate-probing. The capability is real but narrow because husk's
content already discloses the boundary; the prefix's true effect is reliability/mechanisation.

### ★2 Failure-shape banner  => CONVENIENCE, with one caveat. husk masks in TWO styles:
  (a) char-device /dev/null over workdir dotfiles (.bashrc, .mcp.json, .claude/settings.json, even
      "directories" like .claude/agents): these SELF-ADVERTISE — `ls -la` shows `nobody nobody 1,3`
      and `stat` says "character special file", read returns 0 bytes. An agent enumerates the mask
      with `ls -la`+`stat`; a banner describing this shape tells it only what those two commands
      already show. Convenience.
  (b) ENOENT via a freshly-RECONSTRUCTED home: in-cage `/users/cmueller` is a near-empty dir (mtime
      minutes old, contains only .claude); .husk, .husk-review-state, .ssh, real dotfiles are simply
      ENOENT — indistinguishable from never-existed. THIS is where a banner could cross into
      capability: "hidden home looks ENOENT" would turn ENOENT->"hidden" (a bit the FS conceals).
      CAVEAT/limit: I could not retrieve a live banner from inside (HUSK_SESSION_LOG is itself
      ENOENT; no husk CLI on PATH), so I cannot demonstrate the banner AS an instrument. And the
      "home is masked" bit is inferable anyway from `ls -la /users/cmueller` (fresh mtime + near
      empty). A banner would only ADD the *named existence* of specific hidden files — that is A7
      disclosure, and only an oracle if it read back per-file existence, which a static banner does
      not. So: convenience, with the ENOENT-home flagged as the place to keep the banner vague.

### ★3 Query refusal enumerates the allowlist  => CONVENIENCE (as the brief predicted). Input C
dumps all 19 accepted squeue options in one refusal. Counterfactual cost of probing is trivial, so
this is effort saved, not a capability. (Note it ALSO discloses the security-relevant fact that
queries run outside the sandbox with full FS access — that is a rationale disclosure, still
convenience, but see the trade-off note: it teaches the honest agent why the allowlist exists.)

### ★4 "No network is configuration, not transient"  => CONVENIENCE. The posture is disclosed in
prose by the multi-node refusal (msg 5). Knowing egress is off BY DESIGN (not broken) tells an
attacker not to waste attempts probing for a transient hole — it REDIRECTS effort but OPENS
nothing. No door is unlocked; no state is measured repeatably. Convenience for attacker and honest
agent alike. (Could not trigger the exact banner string live from the login shell; egress there
fails as `curl: (7) ... localhost:3128` — a dead forced-proxy, no husk message.)

## THE TRADE-OFF (brief's 4th finding type: less-informative w/o hurting compliance?)

- Stripping the `husk:` prefix / `sbatch failed:` wrapper (reverting to byte-identical `sbatch:
  error:`): would blind the HONEST agent to who refused it — the precise failure husk's own die()
  docstring was written to fix (an agent told `sbatch: error: --qos is not permitted` "went looking
  for a scheduler-shaped workaround"). This REDUCES legitimate compliance. => NOT a free improvement;
  report as a trade-off. The attacker's mechanical classifier and the honest agent's correct
  compliance are THE SAME BIT; you cannot remove one without the other.
- Trimming the query allowlist ENUMERATION (msg 8) to the closest match instead of all 19: costs the
  attacker ~nothing (probing is cheap) AND costs the honest agent little (it usually needs one option,
  not the full set). This is the one place a less-informative message would shave convenience at
  near-zero compliance cost — but it shaves CONVENIENCE, not the demonstrated capability, so the gain
  is marginal.
- Keep vague specifically: the ENOENT-reconstructed-home case (★2b). A banner that NAMES hidden files
  (esp. a credential file) behind an ENOENT mask would convert "looks absent" into "confirmed hidden"
  — the one place the shape-banner could hand over a bit the filesystem conceals.
