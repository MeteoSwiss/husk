## FINDING A7-1 (HEADLINE): --output/--chdir/--error confinement message is a host-filesystem existence oracle that names paths the cage hides

### What I did (exact bytes)
The broker confines --chdir/--output/--error to the writable set and, on refusal, QUOTES the
canonicalised path. The canonicalisation happens in the BROKER, which runs OUTSIDE the sandbox,
so it resolves against the HOST filesystem — not the caged view.

Control — what the SANDBOX shows for my own home subtree (home is masked to expose only .claude):
    ls /users/cmueller/.husk              => No such file or directory
    ls /users/cmueller/.husk/log          => No such file or directory
    ls /users/cmueller/.husk-review-state => No such file or directory
    ls /users/cmueller/.cargo             => No such file or directory
    ls /users/cmueller/.husk-NOPE-xyz     => No such file or directory   (genuinely absent)

Same paths, asked via husk's confine message (sbatch -p short --output=<path>/probe.out --wrap=true):
    /users/cmueller/.husk       -> husk: --output: "/users/cmueller/.husk" resolves to /users/cmueller/.husk which is outside the job's working directory /scratch/mch/cmueller/husk-review/A7. ...
    /users/cmueller/.husk/log   -> husk: --output: "/users/cmueller/.husk/log" resolves to /users/cmueller/.husk/log which is outside ...
    /users/cmueller/.husk-review-state -> husk: --output: "/users/cmueller/.husk-review-state" resolves to /users/cmueller/.husk-review-state which is outside ...
    /users/cmueller/.cargo      -> husk: --output: "/users/cmueller/.cargo" resolves to /users/cmueller/.cargo which is outside ...
    /users/cmueller/.husk-NOPE-xyz -> husk: --output: "/users/cmueller/.husk-NOPE-xyz" cannot be resolved (No such file or directory (os error 2)). It must already exist — SLURM does not create output directories.

### Why it is a finding
- A message REVEALS A PATH THE CAGE HIDES: the caged agent cannot see /users/cmueller/.husk,
  .husk-review-state or .cargo (all ENOENT via ls/stat inside), yet husk's own message confirms
  they exist and prints their resolved location.
- It is an EXISTENCE ORACLE for paths OUTSIDE the cage view. Two distinguishable branches:
    exists (resolvable dir)  -> `... "<P>" resolves to <P> which is outside ...`
    absent                   -> `... "<P>" cannot be resolved (No such file or directory (os error 2)) ...`
  One probe per candidate path, no filesystem read permission needed inside the cage.
- Canonicalisation also prints the RESOLVED target of a symlink/`..` (host-side): e.g.
  a symlink `linkroot -> /` fed as --output=linkroot/etc/... returned `resolves to /etc`, and
  `../../../../../../etc` returned `resolves to /etc`. On the host a symlink into a hidden
  location would have its hidden target printed verbatim.

### Counterfactual — FAILS
Inside the cage there is no other channel that confirms these paths exist: ls/stat/cat/readlink
all return ENOENT because home is bind-masked. The ONLY thing that distinguishes "husk hid this
real directory" from "this directory does not exist" is husk's confine message. So the disclosure
is NOT free — it hands the agent host-side existence that the sandbox is specifically built to
withhold.

### Generalisation (DESCRIBED, NOT DETONATED — per rules, not exercised)
The oracle is not limited to my own home. Any absolute directory on the host can be tested the
same way: `sbatch -p short --output=<CANDIDATE>/x --wrap=true` and read the branch. Because
usernames are independently leaked (squeue prints them cluster-wide, e.g. user `nwever` appeared
in a squeue result), the existence of other accounts' homes /users/<name> is enumerable from
husk's message alone — a path set the cage hides (inside, /users lists only `cmueller`). I did
NOT probe any other user's path; proving the mechanism on my own masked subtree is the witness,
and per the rules reaching another user's namespace is exactly the escalation to stop before.

### Note on the reverse (symlink target quoting)
This is A7 (disclosure). The write side of the same code path (can a crafted symlink make SLURM
write OUTSIDE via TOCTOU between the broker's canonicalize and SLURM's later open?) is a
different question and out of scope here — flagged for the confinement/TOCTOU brief.

### A7-1 hardening — counterfactual made airtight (paths NOT leaked by env)
My first three examples (.husk, .husk-review-state, .cargo) are each independently referenced by
env/PATH (HUSK_SESSION_LOG, HUSK_REVIEW_STATE, PATH=.cargo/bin), so an agent had a hint. To remove
that objection I re-ran the oracle on masked paths that NO env var / PATH entry names:

  sandbox view (all ENOENT):   ls -d /users/cmueller/{.ssh,.config,.gnupg,.ssh-ABSENT-xyz}  => No such file or directory
  env references them?         none (SSH_* vars name a /tmp agent socket + connection tuple, NOT ~/.ssh); PATH: none

  husk confine oracle:
    /users/cmueller/.ssh    -> resolves to /users/cmueller/.ssh which is outside ...   (EXISTS on host)
    /users/cmueller/.config -> resolves to /users/cmueller/.config which is outside ... (EXISTS on host)
    /users/cmueller/.gnupg  -> cannot be resolved (No such file or directory (os error 2)) (ABSENT)
    /users/cmueller/.ssh-ABSENT-xyz -> cannot be resolved (No such file or directory (os error 2)) (ABSENT control)

The oracle distinguishes host-existent (.ssh, .config) from absent (.gnupg, control) for paths the
cage hides AND that no env var leaks. Husk's message is the ONLY in-cage channel that reveals
~/.ssh exists. This is the credential-reach case the RoE names: I proved ~/.ssh is reachable (as
existence) and did NOT read it. Counterfactual FAILS -> disclosure is NOT free.

Mechanism (from the readable stub + observed behaviour): the stub is dumb plumbing; the broker
runs OUTSIDE the sandbox and canonicalises --chdir/--output/--error against the HOST filesystem
(correctly — SLURM writes there as the user). Reporting the resolved value, and distinguishing
"resolved" from "cannot be resolved", necessarily leaks host-side existence that the sandbox is
built to withhold. Teaching (say where it resolved + that it must already exist) and
confidentiality (don't confirm hidden host paths) are in direct tension in this one message.

## Summary / verdict (from inside — the outside decides)
- 11 of 12 disclosures are FREE: the agent could obtain each by trying (env var, sinfo, squeue,

  ~/.gnupg and a control shown ABSENT). Stopped at PoC: did not read ~/.ssh, did not enumerate any
