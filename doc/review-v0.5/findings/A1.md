## FINDING F-A1-01 (CONFIRMED escape): final-component symlink in --output is
## not resolved by husk's confinement, but IS followed by SLURM's open() ->
## file created outside the writable set, as the user, content agent-controlled.

Mechanism / root cause:
  - husk confines the DIRNAME (parent) of --output with an on-disk canonicalise
    and checks it is under the writable set. Evidence it canonicalises only the
    PARENT: probe 1 with --output=/scratch/mch/cmueller/husk-review/<file> (file
    absent) reported it "resolves to /scratch/mch/cmueller/husk-review" (the
    dirname). A not-yet-existing final component cannot be canonicalised, so the
    basename is appended lexically.
  - When the final component ALREADY EXISTS as a symlink pointing outside the
    writable set, husk's check passes (parent A1 is in-bounds) because it does
    NOT resolve that final symlink. SLURM later opens the path as the user with
    O_CREAT|O_WRONLY, which FOLLOWS the symlink, and writes OUTSIDE the cage.
  - This is the brief's F13/F14 shape: two notions of "the same path" (husk's
    canonicalise-the-parent vs the kernel's open-follows-final-symlink) that
    disagree. The agent-supplied value (the pre-planted symlink) becomes the
    thing that dodges the confinement base.
